### Что такое ПО
ПО, которое организует доступ к ресурсам компьютера:
- унифицирует (драйвера, файловая система, чтобы мы не думали, какие он там байты удаляет)
- разделяет (виртуальная память - программа не хочет думать о том, чтобы не залезть в чужую память)
- разграничивает (права доступа пользователей и т.п.)
### Уровни исполнения программ
Чтобы ОС (по факту программа) могла выполнять свои функции, ей нужна поддержка со стороны процессора, поэтому при запуске компьютера исполняемвя часть ОС запускается в привелегированном режиме, которая называется *ядром* (kernel) [[2. Как работает процессор]]

Существуют монолитные ядра (один раз загрузилось в память и управляет программами), в современном Linux ядро - модульное (можем что-то выгружать и загружать куски программ). Также возникает вопрос безопасности, ведь если много кода исполняется в привелегированном режиме, тем больше существенных уязвимостей будет найдено!
### Переносимость и совместимость
Если мы хотим что-то унифицировать, то необходимо договариваться о том, как правильно организовывать единым образом программы. Возникают понятия:
- API (application programming interface) - контракт на уровне souse code (пример: стандартная библиотека языка С)
- ABI (application binary interface) - контракт на уровне машинного кода и представления данных (соглашение о вызовах, поядок загрузки, запуск программы, взаимодействие с ядром ОС)
Говоря про вторую штуку, мы будем хотеть видеть реальное соглашение, мы будем говорить про POSIX (по факту там объясняется, что такое UNIX подобная система). Она была придумана для того, чтобы в UNIX подобных системах гарантированно запускать программы
### Системные вызовы на Linux/amd64
Обращение прикладной программы к ядру называют системным вызовом.

### Файлы
Главная сущность в UNIX подобных системах, все представлено через эту абстракию.

Файл - последовательность байт, к которой ОС предоставляет доступ посредством файловый операций (read - чтение из файла, write - пишет в файл, если у файла есть позиция чтения-записи, то lseek - сдевигает позицию чтения-записи на введенное кол-во байт). 

Конец файла называется EOF. Не существует символа специального, это ситуация, когда read возвращает 0
