### Многофайловая сборка
Каждый ассемблерный файл (`.S`) ассемблер превращает в объектный файл с машинным кодом (`.o`), а потом другая программа — «компоновщик» или «линкер» — объединяет объектные файлы в исполняемый. 

Метки, которые должны быть доступны из других файлов, необходимо объявлять `.global`, что позволяет компоновщику собирать исполняемый файл.
### Флаги
Отдельные биты специального регистра `rflags` называются флагами. 

Большинство арифметических инструкций в результате вычисления результата инструкции устанавливают арифметические флаги.

Флаг _ZF_ (zero) устанавливается, если в результате операции был получен нуль.

Флаг _SF_ (sign) устанавливается, если в результате операции было получено отрицательное число.

Флаг _CF_ (carry) устанавливается, если в результате выполнения операции произошел перенос из старшего бита результата. Например, для сложения CF устанавливается, если результат сложения двух беззнаковых чисел не может быть представлен беззнаковым числом соответствующей разрядности.

Флаг _OF_ (overflow) устанавливается, если в результате выполняния операции произошло переполнение знакового результата. Например, при сложении OF устанавливается, если результат сложения двух знаковых чисел не может быть представлен знаковым числом соответствующей разрядности.

Обратите внимание, что и сложение add, и вычитание sub устанавливают одновременно и флаг CF, и флаг OF. Сложение и вычитание знаковых и беззнаковых чисел выполняется совершенно одинаково, и поэтому используется одна инструкция и для знаковой, и для беззнаковой операции.

```Assembler
stc  // установить CF
clc  // сбросить CF
setc al  // установить al в 0 или 1 в зависимости от флага
// seto, setz, ...
```
### Переходы
#### Безусловный переход `jmp`
Инструкция `jmp` выполняет **безусловный переход** к другому месту в коде. Она изменяет значение `RIP`, передавая управление другой инструкции.
##### Переход по метке
Простейший способ указать направление перехода — использовать именованную метку. 

**Пример:**

```x86asm
section .text
global _start

_start:
    mov rdi, 11        ; присваиваем 11
    jmp завершение     ; переход по имени метки
    mov rdi, 99        ; эта строка не выполнится

завершение:
    mov rax, 60        ; вызов завершения
    syscall
```
##### Переход по адресу из регистра (косвенный)
Можно использовать значение, хранящееся в регистре, как адрес для перехода. Это позволяет выполнять **непрямой переход**, то есть переход не к конкретной строке кода, а к адресу, вычисленному во время выполнения:

```x86asm
section .text
global _start

_start:
    lea rbx, [метка]   ; загружаем адрес метки в регистр
    mov rdi, 22
    jmp rbx            ; переход по адресу в RBX
    mov rdi, 99        ; эта строка не выполнится

метка:
    mov rax, 60
    syscall
```

✅ **Допустимо**, если:
- используется **64-битный регистр** (`jmp rbx`, а не `jmp ebx`);
- адрес в регистре указывает на **валидный участок кода**.
##### Переход по адресу из памяти
Иногда необходимо совершить переход по адресу, хранящемуся в **переменной**. В таком случае используется косвенная адресация с помощью квадратных скобок:

```x86asm
section .text
global _start

_start:
    mov rdi, 23
    jmp [переход_по_адресу]  ; загружаем адрес из памяти
    mov rdi, 99              ; не будет выполнено

метка:
    mov rax, 60
    syscall

переход_по_адресу: dq метка  ; переменная с адресом
```

✅ **Разрешено**, если:
- переменная `переход_по_адресу` находится в секции `.data` (а не `.text`);
- она содержит корректный **64-битный адрес инструкции** (`dq`).

![[Pasted image 20250729175749.png]]

В `jmp [имя]` переменная `имя` должна содержать именно **адрес инструкции**, а не значение или смещение.
#### Условные переходы
Эти условнее переходы совершаются, если выполняется условие и наоборот. После `jno` стоят особняком переходы, которые срабатывают правильно после операции вычитания. 

Так же стоит запомнить, что для корректного исполнения логики, надо делать условный переход сразу после придуманной арифметической операции, потому что условный переход обращается к флагам, который выставляются каждую арифм. операцию.

#### Как компьютер понимает, что одно число больше другого
Если сравниваются два знаковых числа, то для их порядка используются флаги **SF** и **OF**:
- Если **SF** и **OF** различны, значит, первый операнд меньше второго.
- Если **SF** и **OF** одинаковы, то первый операнд больше или равен второму.

Для беззнаковых чисел используется флаг **CF**:
- Если **CF** установлен, то первый операнд меньше второго.
- Если **CF** сброшен, то первый операнд больше или равен второму.

Для большего понимания можно привести пример использования cmp для сравнения знаковых и беззнаковых чисел (для этого рассмотрим 8-битные числа, то есть числа в диапазоне от 0 до 256 - беззнаковые числа, и от -127 до 128):

**1. Для знаковых:**

_Ситуация 1_  
`cmp    100, -50  // 100 - (-50) = 150` 

при вычитании получили положительное число, т.к. знаковых 8 битные числа находятся в интервале от -127 до 128, то получили знаковое переполнение. Значит установлен OF, SF будет тоже установлен, т.к. 150 = 10010110₂, старший бит равен единицу.

Имеем OF == SF    =>     Первый операнд больше второго, что истина

_Ситуация 2_

`cmp    -50, 100  // -50 - 100 = -150`

при вычитании получили отрицательное число, и т.к. знаковых 8 битные числа находятся в интервале от -127 до 128, то получили знаковое переполнение. Значит установлен OF. Далее рассмотрим, что произошло с SF.  
  
Нужно перевести число в двоичное представление (формура: -x = ~x + 1, где ~ - операция инверсии битов). Так как число непредставимо в 8 битах, то нам необходимо представлять число -150 по модулю 256. 

-150 mod 256 = 106, а это число положительное, значит знаковый бит равен нулю.

Получаем SF != OF  =>  второй операнд больше первого.  
  
**А что будет, если числа будут "убираться" в 8 - битные числа (да и для числа любой битности)**

_Ситуация 3_  
Пусть имеем 45 и -50, тогда мы не будем выходить за рамки 8-битных чисел

`cmp    45, -50 // 45 - (-50) = 95`

Получили следующее: знаковый бит равен нулю (число положительное, SF = 0), переполнения так же нет (OF = 0)  
SF == OF  => первый операнд больше второго  

_Ситуация 4_

`cmp    -50, 45 // -50 - 45 = -95`

Получаем, что знаковый флаг выстален, а флаг переполнения нет! OF != SF  =>  второй операнд больше первого

**2. Для беззнаковых**

_Ситуация 1_  
`cmp    10, 50  // 10 - 50 = -40`

Получили, что результат вычитания беззнаковых 8 битных чисел (от 0 до 256) не попадает в этот диапазон, можно понять, что число будет представлено как -40 mod 256 = 216 - то есть положительное число. Значит, имеем беззнаковое переполнение (произошёл заем - borrow, из старшего бита). CF = 1  =>  первый операнд больше второго.

_Ситуация 2_

`cmp    50, 10 // 50 - 10 = 40`

Получили, что результат вычитания положительный, значит заёма из старшего разряда не было! CF = 0  =>  первый операнд больше второго.

**Программа:**
Посчитаем до 20
```asm
    .intel_syntax noprefix
main:
    xor r12d, r12d
loop:
    add r12d, 3
    mov edi, r12d
    call writei32
    mov edi, r12d // т.к. могло затереться, то снова копируем
    sub edi, 20  // вычли, чтобы установились флаги
    jl loop      // если флаги выставлены, то тогда ->
    call finish
    .global main
```

Так же для выставления флагов можно использовать недеструктивные операции:

```asm
    cmp dst, src  // недеструктивная версия sub
    test dst, src // недеструктивная версия and
```
## Условные инструкции
[см. справочник](https://www.felixcloutier.com/x86/cmovcc)

Инструкция `cmov` (conditional move if что-то) работает как `mov`, если нужные флаги выставлены, или как `nop`, если сброшен.

Инструкция работает только с регистрами или памятью (где память не в операнте DST), то есть можно:
```asm
	cmovg    rbx, rax
	cmovl    rbx, [0x40100]

	cmovl    [0x40100], rbx  // НЕЛЬЗЯ!
	cmovl    rbx, 1          // НЕЛЬЗЯ!
```

Основные типы инструкций `cmov`:
1. **cmovc / cmovb / cmovnae**: копирует значение, если установлен флаг переноса (CF = 1).
2. **cmovnc / cmovnb / cmovae**: копирует значение, если флаг переноса не установлен (CF = 0).
3. **cmovz / cmove**: копирует значение, если установлен флаг нуля (ZF = 1).
4. **cmovnz / cmovne**: копирует значение, если флаг нуля не установлен (ZF = 0).
5. **cmovs**: копирует значение, если установлен флаг знака (SF = 1).
6. **cmovns**: копирует значение, если флаг знака не установлен (SF = 0).
7. **cmovo**: копирует значение, если установлен флаг переполнения (OF = 1).
8. **cmovno**: копирует значение, если флаг переполнения не установлен (OF = 0).

Для сравнения значений между операндами, процессор также поддерживает следующие инструкции:
- **cmova**: копирует значение, если первый операнд больше второго (CF = 0, ZF = 0).
- **cmovg**: копирует значение, если первый операнд больше второго (SF = OF и ZF = 0).
- **cmovl**: копирует значение, если первый операнд меньше второго (SF ≠ OF).
### Инструкция `loop` для организации цикла
Конфликтует с simpleio...

Инструкция `loop` в архитектуре x86-64 позволяет организовать цикл с минимальным количеством строк кода. Она автоматически уменьшает значение регистра `RCX` на единицу и выполняет переход к указанной метке, если после уменьшения `RCX` не равен нулю. Это удобно для простых итеративных операций, где не требуется сложная логика проверки.

Важно также помнить, что **`loop`** не проверяет флаги состояния, она лишь выполняет переход в зависимости от значения **RCX**.

**Пример**:
```x86asm
global _start

section .text
_start:
    mov rcx, 5        ; Инициализация счетчика на 5
    mov rsi, 0        ; Начальное значение

repeat_loop:
    add rsi, 2        ; Действие внутри цикла
    loop repeat_loop  ; RCX уменьшается, переход, если RCX ≠ 0

    mov rax, 60
    syscall
```
#### Расширенные формы: `loope` и `loopne`
Эта инструкция так же испольует `rcx` в качестве счетчика.

Эти инструкции также выполняют цикл, но с дополнительными условиями, основанными на флаге **ZF** (нулевой флаг). Инструкция **`loope`** выполняет переход, если **ZF** установлен (т.е. результат последней операции равен нулю). В то время как **`loopne`** выполняет переход, если **ZF** сброшен (результат последней операции не равен нулю).

То есть инструкция `loopne` прыгнет на метку или область памяти, если ZF != 0 и `rcx != 0`. Так же и с инструкцией `loope`: если ZF = 0 и `rcx != 0`
#### Условная проверка счетчика: `jrcxz`
Это инструкция, которая проверяет значение регистра **RCX** перед началом цикла. Если **RCX** равно нулю, то она прыгает на указанную метку, что удобно для проверки предусловий. Она не изменяет флаги состояния и работает исключительно с содержимым **RCX**.
